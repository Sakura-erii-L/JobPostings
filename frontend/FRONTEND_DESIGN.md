# 前端设计提案

## 1. 定位与依据

本提案把 JobPostings 定位为“招聘资料工作台”：安静、清晰，方便连续检索招聘信息、核对来源并推进个人求职。依据是 [`docs/FRONTEND_UI_SUMMARY.md`](../docs/FRONTEND_UI_SUMMARY.md) 的静态代码审计，重点参考 `frontend/src/main.tsx`、`styles.css` 和 `queue.css`。审计没有运行时截图或真实数据验证，因此本文是未来设计提案，不代表 UI 已实现。

设计保留现有业务功能、权限边界、React/Vite 架构和页面状态切换，减少深蓝渐变侧栏、重复卡片、胶囊标签、装饰性指标和英文 eyebrow 带来的 SaaS Dashboard 感。信息层级服务于“找到资料、确认事实、采取下一步”，而不是增加装饰。

## 2. 视觉规范

以下是建议 token，不是当前实现的承诺：画布 `#F7F8FA`，表面 `#FFFFFF`，主文字 `#202733`，次文字 `#596575`，分隔线 `#DDE2E8`，强调色 `#2457A6`。成功、警告和错误只表达状态，必须同时有文字或动作说明，不能依靠颜色单独传达。

不使用渐变；普通内容不加阴影，浮层只使用很弱的阴影。普通控件圆角 6px，独立面板 8px；间距限定为 4/8/12/16/24/32px。使用 `Microsoft YaHei`、`PingFang SC`、`system-ui` 等中文系统字体，不加载外部字体；正文 14px、辅助文字 12px、页面标题 22px，正文行高 1.5，金额、日期和计数可使用等宽数字。选中项使用浅强调底色、强调文字或竖线；按钮焦点使用 2px 强调色轮廓并保留 2px 偏移。

图标采用少量统一的线性内联 SVG并配合文字，不引入组件库或图标依赖。彩色装饰、巨型欢迎头图和没有业务价值的图表不加入。

## 3. 应用壳与渐进展示

浅色导航约 216px 宽，以边线与内容分隔。一级导航分为“求职”：企业与岗位、招聘时间轴、求职进度；管理员的“数据管理”仅包含导入、待审核、处理队列。底部只有一个“设置与管理”入口，删除独立的管理台、系统设置和账户安全入口。待审核和处理队列保留为独立高频入口，不在新中心重复出现。旧快捷入口若保留，须定位到中心内对应分区。

“设置与管理”是一个中心，使用二级菜单和单一内容区：桌面端侧边显示文字子导航，窄屏显示带当前分区名称的选择菜单，不堆叠表单或挤成长 tabs。导航最多两层，常用内容直达；tabs 只用于同一对象的平级视图；折叠面板只放补充说明、高级参数和日志；抽屉只用于临时查看证据等上下文，长表单不放进窄抽屉。避免折叠套折叠和多层子菜单。摘要必须带关键状态、数量、异常和下一动作，错误与待审核提示不能藏在“更多”或折叠里，敏感值不出现在摘要。

页面头只保留标题、必要说明和一个主要操作。次要操作用文字或描边按钮；批量操作选择后出现，低频操作收进“更多”，危险项与常规项分隔。指标缩成工具条计数并保留筛选语义；同类条目用留白和分隔线区分，卡片只承载独立任务或对象，避免容器嵌套。按钮文案描述结果或影响，如“加入队列（3）”“重试任务”“保存连接设置”，不只依赖图标。

## 4. 设置与管理中心

中心默认进入“账户与安全”；同一会话再次打开时恢复上次仍有权限的分区。普通用户只看到账户与安全，不显示空的管理员分组；权限和数据可见性以现有后端规则为准，不新增权限功能，也不新建管理总览。

| 分区 | 可见范围与内容 |
| --- | --- |
| 账户与安全 | 所有用户，仅管理自己的账户安全信息。 |
| 邀请与权限 | 管理员，将现有管理台的邀请和权限能力迁入，不扩展权限。 |
| 连接服务 | 管理员，TraceMemo、通用模型 API、WebDAV、SMTP、Agent API。 |
| 处理与隐私 | 管理员，同步隐私和处理器并发。 |
| 存储与备份 | 管理员，本地存储、备份和清理。 |

只显示当前选中的分区。连接服务先显示服务名、真实配置状态和“编辑”行，进入一次一个服务的表单，返回时保留列表位置；高级字段折叠但已配置状态摘要可见，验证错误自动展开并定位字段。每个分区独立保存/测试并反馈。编辑未保存切换时提示“保存、放弃或留在当前页”，不静默丢弃；密钥草稿不得写入 URL 或本地持久化。危险操作单独分区，确认对象、范围和影响后再执行。

## 5. 页面方案

| 页面 | 设计方向 |
| --- | --- |
| 企业与岗位 | 默认紧凑列表，卡片视图留待评估。显示名称、行业/地点和岗位数，摘要只用已有字段，缺失显示“未提供”。搜索、筛选和排序紧邻结果；进入详情再返回时保留条件和滚动位置。 |
| 企业详情 | 顶部只放企业名、关键事实和主要动作；下方用“岗位/招聘动态/企业资料”平级 tabs，默认岗位。岗位页先给公共招聘条件摘要和岗位列表，全文可展开；企业资料集中概览、核查和专业需求，不同时铺开全部内容。证据入口显示来源数，桌面上下文侧栏查看，窄屏全宽查看，关闭返回原焦点并保留 tabs、筛选和滚动。推测必须标为推测。 |
| 招聘时间轴 | 默认只显示事件摘要，按日期分组并保留清晰时间列、周/列表切换；一次只按需展开一个事件，类型用轻量标签表达。 |
| 求职进度 | 桌面四列：感兴趣、已投递、面试中、Offer；窄屏改为状态 tabs 加单列，显示各列计数并保留全部状态。 |
| 导入招聘信息 | 默认只选中一个入口，只显示当前方式和群聊当前步骤。群聊流程是“选群 → 选消息 → 确认入队”，保留已选数量并支持返回上步；不同时渲染三套表单，入队反馈提供查看队列入口。 |
| 处理队列 | 单行先显示来源摘要、状态、当前步骤、已有字段中的更新时间、错误和下一动作；展开单个任务查看原文、证据、子任务，日志按需打开，刷新不重置展开位置。 |
| 待审核 | 保留原始证据与提取结果以便核对，待确认项直接可见；长原文和完整载荷按需查看，窄屏依次排列。 |

列表先展示名称、地点、数量和更新时间等已有事实，不为填满空白编造摘要。来源、证据、原始消息和模型结果维持可追溯关系，证据缺失要明确显示缺失。设置旧内容全部引用上述中心分区，不保留重复入口。用内容层级、留白和分隔线建立秩序，避免增加装饰容器。

## 6. 交互与响应式

复用 `1000px` 和 `680px` 断点。`681–1000px` 可收窄导航但保留文字；`<=680px` 用带文字的菜单按钮打开导航抽屉，当前页标题和设置分区名称可见，并完整处理关闭、焦点返回、Escape 和焦点限制。触摸目标至少 44px，页面不得横向溢出，局部宽表独立滚动。

所有可交互项可由键盘到达，统一提供 `:focus-visible`；展开按钮声明 `aria-expanded`，图标按钮提供 accessible name。异步按钮保持 loading 并防重复提交；成功用行内确认或低干扰通知，错误就近持久显示并可重试，避免 `alert` 和遮挡页面头部。长任务以真实队列状态为准。加载、空数据、筛选无结果和失败分开呈现，并给出下一步。网络请求期间不清空已有结果；通知不应成为唯一反馈。

## 7. 落地顺序与未来验收

这是未来实施顺序，本次只交付文档。P0 处理新一级导航、设置与管理二级框架、权限可见性、未保存切换和通用渐进展示；P1 迁入各设置分区并完善企业详情、导入和队列；P2 收尾时间轴与看板。

未来验收覆盖 360、680、1000、1440 宽度，普通用户与管理员权限，键盘完整操作，以及搜索进入详情返回、群聊导入查看队列、失败重试和设置保存失败。还要确认三个旧入口已合并且无重复、功能未丢，普通用户无管理员分区且数据权限不变，只显示当前分区并保留切换后的状态，未保存切换支持保存/放弃/留在当前页三分支，高级字段出错自动显现，窄屏子菜单可键盘使用，错误不会因折叠被隐藏。正文对比度至少 4.5:1，焦点和控件边界至少 3:1。实施后运行 `frontend` 下的 `npm run typecheck` 和 `npm run build`；这些是未来标准，当前没有据此宣称已通过。

## 8. 实施记录（续作，静态设计与隔离验证）

本轮修正了账户密码校验失败不回调导致保存状态锁死的问题；中心触发保存也执行密码长度与一致性校验，并持续显示保存中。一级导航和浏览器后退离开设置进入保存、放弃、留在当前页三分支，保存失败留在设置并保留输入。设置中心按请求计数一次性消费保存请求，首次挂载不自动 PUT；连接服务只提交已修改服务，加载失败不显示可编辑默认表单。移动端 dirty 导航会先关闭导航抽屉，再把焦点移到确认对话框。

`frontend/verification/mock_ui_check.py` 使用现有 Python Playwright 和系统 Chrome，通过拦截 `/api/v1/*` 返回隔离 mock 数据。实际命令为：`$env:PYTHONUNBUFFERED='1'; .venv\Scripts\python.exe -u frontend\verification\mock_ui_check.py`。结果为普通用户和管理员在 360、680、1000、1440 共 8 个场景通过；每个场景首次进入设置无 PUT，普通用户密码校验失败不发 `/auth/password`；另通过密码保存成功、mock 400 失败保留输入、留在当前页、放弃修改和连接服务切换无额外 PUT。追加命令 `.venv\Scripts\python.exe -u frontend\verification\mock_ui_check.py --business` 通过了企业详情三 tabs、来源证据按需打开并关闭回焦、返回后搜索词保留、时间轴单事件展开、桌面看板、窄屏看板状态切换、群聊选群→选消息→确认入队、队列摘要/错误/当前步骤、原文默认收起、单任务日志按需展开。该业务脚本只产生 mock 的群组保存和消息入队请求，没有访问真实后端；成功截图位于 `frontend/verification/artifacts/`。

本轮还执行了 `npm run typecheck`、`npm run build`、`python -m py_compile frontend/verification/mock_ui_check.py` 和 `git diff --check`，均通过。验证使用系统 Chrome；Playwright 自带浏览器未下载，未访问真实后端写接口，因此真实 API 权限、生产群聊、真实队列刷新位置和生产数据仍未做运行时验证。设计中的完整键盘覆盖、焦点对比度和真实后端场景仍属于未来验收标准，本文不将其写成已通过。
